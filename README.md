# Tempo 使用手册

[日本語版](README.ja.md)

Tempo 是一个在浏览器里使用的甘特图（工程表）工具，用来安排任务日程、看进度、尽早发现延误。

- **打开方式**：双击本文件夹里的 `Tempo.html`（推荐 Chrome 或 Edge）。不需要安装，也不需要联网。
- **数据保存**：自动保存在这台电脑的浏览器里（顶部右侧显示「このブラウザに保存」）。
- **界面语言**：日语。本手册里「」中的文字就是界面上显示的文字。

本手册分两部分：

- **第一部分**：给人看的操作说明
- **第二部分**：给 AI（或需要批量写入数据的人）看的数据格式说明

---

# 第一部分：操作说明

## 1. 画面构成

```
┌─────────────────────────────────────────────────────────────┐
│ Tempo [项目选择▼] [＋プロジェクト] [設定] [保存] [担当筛选▼] [日|週|月] [今日] [＋タスク] │ ← 顶部栏
│ 期間 … 次の節目 … 全体進捗 …%  [状态标签]                    │ ← 统计栏
│ [↶][↷] [复制][粘贴] [插入][缩进][移动] [关联] [担当] [编辑][＋][×] │ ← 编辑工具栏
├──────────────────────────┬──────────────────────────────────┤
│ 任务表                    │ 时间轴（横条）                       │
│ タスク 担当 開始 終了 日数 進捗 │ ███████ 2/28 (土) 0% 18営業日 担当   │
└──────────────────────────┴──────────────────────────────────┘
```

## 2. 项目

- **新建**：点「＋ プロジェクト」
- **切换**：顶部左侧的下拉框
- **改名 / 删除 / 备份**：点「設定」打开右侧面板
- 删除项目需要按两次确认，**删除后不能撤销**

## 3. 任务的基本操作

| 想做的事 | 操作 |
|---|---|
| 新增任务 | 点「＋ タスク」或任务表最下方「＋ タスクを追加」 |
| 选中任务 | **单击**任务行或横条（Ctrl 多选，Shift 连选） |
| 打开详细编辑 | **双击**任务行或横条，或选中后按 Enter |
| 改名 | 右键任务行 →「名前を変更」，输入后按 Enter |
| 改父任务的颜色 | 父任务按层级自动着色（第 1 层蓝、第 2 层青绿、第 3 层黄）；想换颜色时右键父任务的行 →「色」选颜色（先预览）→「決定」保存；「既定の色」= 恢复该层级的默认色 |
| 改日期 | 拖动横条中间 = 整体移动；拖动横条两端 = 改开始日 / 结束日。**多选后拖动其中一个横条的中间，选中的任务一起移动**（选中父任务时，它下面的子任务也一起移动） |
| 改进度 | **双击**横条右侧的「N%」→ 拉动滑块（「戻す」= 恢复原值） |
| 指定担当 | 单击任务表「担当」列的框 → 点选成员（可多选） |
| 调整顺序、设为子任务 | 在任务行上**按住左键约 0.35 秒**，拖到目标行：上部 = 放到上方，下部 = 放到下方，中间 = 成为它的子任务。先 Ctrl / Shift 多选，再长按其中一行，选中的任务会一起移动 |
| 删除 | 选中后按两次 Delete，或点工具栏 × 两次 |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Y |

单击只会选中，不会打开编辑，所以拖动时不用担心误操作。

## 4. 编辑工具栏

先选中任务，再点按钮。

| 按钮 | 作用 | 快捷键 |
|---|---|---|
| ↶ ↷ | 撤销 / 重做 | Ctrl+Z / Ctrl+Y |
| 复制 / 粘贴 | 复制选中任务（含子任务），粘贴到选中行下方 | Ctrl+C / Ctrl+V |
| 上方插入 / 下方插入 | 在选中行上方或下方插入新任务 | |
| 缩进 / 取消缩进 | 设为上一行的子任务 / 提升一级 | Tab / Shift+Tab |
| 上移 / 下移 | 在同级之间移动 | Alt+↑ / Alt+↓ |
| 关联 / 取消关联 | 按选中的先后顺序把任务串成前后工序（图上画箭头）；父任务不参与 | |
| 添加担当 / 移除担当 | 给选中的多个任务一起增减担当 | |
| 编辑 | 打开详细编辑面板 | Enter |
| ＋ / × | 新增任务 / 删除（按两次） | Delete 两次 |

**关联的效果**：前工序的结束日推迟后，后工序会自动往后顺延（工作日数不变）。只会往后推，不会自动提前。

## 5. 父任务与子任务

- 有子任务的任务就是父任务，横条显示为细的汇总条
- 父任务的开始日、结束日、进度、担当**自动由子任务计算**，不能直接修改
- 最多 4 层
- 点父任务左侧的 ▾ / ▸ 可以折叠 / 展开
- **父任务的颜色**：任务一变成父任务，就**自动**按层级显示默认色：第 1 层（最上层）蓝 `#6685ff`、第 2 层青绿 `#20c997`、第 3 层黄 `#fab005`，嵌套的父任务也能区分开。这一行左侧有色条和浅色底，汇总横条也是这个颜色，一眼就能看出是父任务。想换颜色时右键父任务的行 →「色」选颜色 →「決定」；「既定の色」= 恢复该层级的默认色。只有父任务的右键菜单里才有「色」
  - 选颜色时只是预览（行和横条马上变色），按「決定」才保存；不按「決定」就关闭菜单（点别处或 Esc），颜色恢复原样

## 6. 看懂颜色和状态

### 横条颜色

| 颜色 | 意思 |
|---|---|
| 蓝色 | 进度跟得上 |
| 蓝色，右端渐变成紫 → 粉红 | 进度落后。越偏粉红落后越多（分 4 档） |
| 红色 → 黄色 | 已过结束日，还没完成（期限切れ） |
| 灰色 | 已完成 |
| ◆ | 任务里程碑（单日的节点任务） |
| 细的蓝 / 青绿 / 黄色条（行左侧也有同色竖条） | 父任务的汇总条，按层级默认着色，右键可改色（见第 5 节） |

「落后」的意思是：按时间推算应该完成的量，多于实际进度。比如 10 个工作日的任务过了 5 天，进度还是 0%，就算落后。

### 状态（任务名左边的圆点、顶部的状态标签）

| 状态 | 条件 |
|---|---|
| 完了（灰） | 进度 100% |
| 未着手（蓝） | 还没到开始日 |
| 期限切れ（红） | 已过结束日，未完成 |
| 進捗遅れ（橙） | 实际进度比应有进度落后超过 10 个百分点 |
| 順調（绿） | 其他情况 |

点顶部的状态标签可以只显示该状态的任务，再点一次取消。

### 其他

- **工作日**：自动扣除周六、周日、日本法定节假日（已内置到 2028 年）和本项目的公司休日（见第 7 节）
- **全体進捗**：所有任务按工作日数加权的平均进度
- **时间轴**：灰底 = 周末，粉底 = 节假日，自选颜色 = 公司休日，红线 = 今天。点「今日」回到今天

## 7. 项目里程碑（大节点）

用来标记整个项目的重要日期（交付日、中期检查等）。

- **添加**：点时间轴顶部的日期 → 选颜色、输入标题 →「登録する」
- **修改 / 删除**：点已有的旗帜
- 顶部会显示下一个节点和剩余天数：「次の節目 3/15 α版提出（あと 12 日・8 営業日）」

### 公司休日

公司自己的休息日（创立纪念日、年末年初、夏季休假等），**每个项目分开设置**。日本法定节假日已内置，不需要再加。

- **设为休日**：点时间轴顶部的日期 → 弹窗里「会社の休日」选颜色 →「休日にする」
- **取消**：再点那一天 →「休日を解除」
- **改颜色**：再点那一天 → 改颜色，立即生效。下次新设休日时默认用最后选的颜色
- 效果：这一天显示为所选颜色，不算工作日（工作日数、延误判定、关联顺延都会按它计算）
- 撤销：Ctrl+Z

## 8. 成员名单

先登记成员，之后在任务里直接点选。

1. 点「設定」→「メンバー」输入名字 →「追加」（用「、」隔开可一次加多人）
2. 在任务表的「担当」框里点选

从名单删除某人，不会影响已经分配给他的任务。

## 9. 数据保存与备份

- 所有修改**自动保存**，不需要手动保存
- 数据存在**这台电脑的这个浏览器**里。换浏览器、换电脑、清除浏览数据后就看不到了
- **备份到文件夹（推荐，Chrome / Edge）**：「設定」→「自動バックアップ」→「保存先フォルダを選ぶ」，选一个文件夹。备份文件都存在这个文件夹里，内容都是**全部项目**：

  | 文件 | 什么时候写 | 数量 |
  |---|---|---|
  | `auto.backup.json` | 每次修改后自动写（约 1 秒后） | 只有 1 个，每次覆盖，始终是最新状态 |
  | `2026-09-29_10-35-12.backup.json` | 点顶部的「保存」按钮时，文件名是按下的时间 | 每按一次多一个，不覆盖。想留版本时就按一下 |
  | `before-restore.backup.json` | 「バックアップから復元」读取之前，保存读取前的状态 | 只有 1 个，每次覆盖，只保留最近一次读取前的状态 |

  - 还没选文件夹时，第一次按「保存」会先让你选
  - 浏览器重启后第一次修改或保存时，Chrome 会问一次是否允许访问这个文件夹，点「許可」即可
  - 「設定」里会显示保存的文件夹、自动备份的时间、最后一次手动保存的文件名
  - 文件夹放在仓库里也没关系：`*.backup.json` 已被 `.gitignore` 排除，不会被提交
- **从备份恢复**：「設定」→「バックアップから復元」→ 选择想回到的那个 `.backup.json`。文件里的项目会覆盖同 ID 的项目，其他项目保持不变。读取后 `auto.backup.json` 会变成读进来的内容，所以已设置备份文件夹时，读取前的状态会先存到 `before-restore.backup.json`；选错了文件时，读取它就能回到读取前
- **单个项目的备份**：「設定」→「JSONをコピー」，把内容粘贴到文本文件保存；恢复时粘贴到「データ（JSON）」框 →「貼り付けたJSONで置き換え」
- 移动或改名 `Tempo.html` 不会丢数据（同一浏览器里所有本地文件共用一份存储）

### Excel（.xlsx）读取与导出

格式与 Brabio 的 Excel 导出相同：第 1 行项目名，第 2 行期间，第 3 行表头（タイプ / アウトライン / ID / タイトル / 開始日 / 〆切日 …），第 5 行起是数据（项目行 → 里程碑 → 文件夹 / 任务）。

- **导出**：「設定」→「Excel（.xlsx）」→「書き出す」。文件名为「项目名 (开始日～结束日).xlsx」
- **读取**：「設定」→「読み込んで置き換え」→ 选择 .xlsx。Brabio 导出的文件也可以直接读取
- 读取会**替换当前项目的全部任务和里程碑**，项目名和成员名单也按文件更新。读错了可以按 Ctrl+Z 撤回
- 读取后提示「N 件のタスクを読み込みました」；缺少标题或日期的行不读取，会提示跳过了几件
- 按表头名找列，所以在 Excel 里调换列的顺序也没关系；日期写成 `2026/09/14` 或 Excel 的日期格式都可以
- 对应关系：アウトライン 1 = 顶层任务；メンバー 多人时换行分隔；内容 = 备注（里程碑行则是颜色）；リンクID = 关联
- 不导出 Brabio 右侧按天画的甘特图；最后多两列「マイルストーン」（◆ = 里程碑任务）和「色」（父任务的颜色，如 `#7048e8`），Brabio 没有这两项
- ステータス、状況、进度等由 Tempo 计算后写出，与 Brabio 的算法不同，数字可能略有差别
- 从 Brabio 导出时请把期间设宽：Brabio 只导出期间内的任务
- 公司休日不导出到 Excel（Brabio 格式没有对应的列）；读取 Excel 时，已设的公司休日保持不变

**发布为 Artifact（claude.ai）时**：数据改为存在云端，顶部显示「クラウドに自動保存」，打开链接的人看到同一份数据；没有编辑权限的人显示「閲覧のみ」。

## 10. 常见问题

| 问题 | 原因 / 解决 |
|---|---|
| 父任务的日期改不了 | 父任务由子任务自动计算，请改子任务 |
| 拖动任务时变成了选中文字 | 需要按住约 0.35 秒再拖 |
| 进度「N%」单击没反应 | 需要**双击** |
| 担当框里没有想要的人 | 先到「設定」→「メンバー」登记，或在详细编辑里手动输入 |
| 数据不见了 | 是否换了浏览器或清除了浏览数据？用「バックアップから復元」或保存的 JSON 恢复 |
| 横条突然变粉 / 变红 | 进度落后或已过期，更新进度即可 |

# 第二部分：数据格式（给 AI 看）

本部分说明 Tempo 的项目数据结构，以及怎样把 AI 生成的数据写进 Tempo。

## 11. 写入方式

### 方式 A：通过 JSON 粘贴（本地使用时，推荐）

1. 在 Tempo 里打开目标项目（新项目先点「＋ プロジェクト」）
2. 点「設定」→「JSONをコピー」，**先保存一份当前数据作备份**
3. AI 按第 12 节的格式生成**完整的**项目 JSON（在当前数据基础上修改，而不是只写新增部分）
4. 把 JSON 粘贴到「データ（JSON）」框 →「貼り付けたJSONで置き換え」
5. 画面提示「N 件のタスクを読み込みました」，确认件数正确；如有问题按 Ctrl+Z 撤回

注意：

- 「置き換え」会**替换当前项目的全部任务**。没写进 JSON 的任务会消失
- `milestones`、`holidays`、`members`、`name` 只有在 JSON 里出现时才替换；不写则保持原样
- 也可以只粘贴任务数组 `[ {...}, {...} ]`，这时只替换任务
- **缺少任务名或日期格式不对的任务不会被读取**；读取后会提示跳过了几件，请核对件数

### 方式 B：发布为 Artifact 后直接写云端数据库

- 集合（collection）名：`projects`
- 文档 ID = 项目 ID，一个项目一个文档
- 文档内容 = 第 12 节的项目对象（不含 `id`），另加 `updatedAt`（毫秒时间戳）
- 写入后，打开页面的人会实时看到变化
- 同样**整份替换**：请先读取现有文档，在其基础上修改后写回

## 12. 数据结构

### 项目

```json
{
  "name": "角色制作",
  "members": ["张三", "李四", "王五"],
  "tasks": [ ...任务，见下 ],
  "milestones": [ ...项目里程碑，见下 ],
  "holidays": [ ...公司休日，见下 ]
}
```

| 字段 | 类型 | 必须 | 说明 |
|---|---|---|---|
| name | 字符串 | 否 | 项目名 |
| members | 字符串数组 | 否 | 成员名单（担当的候选人） |
| tasks | 数组 | **是** | 任务列表，**顺序 = 画面上的显示顺序** |
| milestones | 数组 | 否 | 项目里程碑 |
| holidays | 数组 | 否 | 公司休日（本项目专用） |

### 任务

```json
{
  "id": "t5",
  "name": "角色粗模制作",
  "start": "2026-02-02",
  "end": "2026-02-28",
  "progress": 0,
  "assignees": ["张三"],
  "level": 0,
  "milestone": false,
  "memo": "",
  "deps": ["t2"]
}
```

| 字段 | 类型 | 必须 | 说明 |
|---|---|---|---|
| id | 字符串 | 建议 | 项目内唯一。省略时自动生成，但这样 `deps` 就无法引用它 |
| name | 字符串 | **是** | 任务名，不能为空 |
| start | 字符串 | **是** | 开始日，格式严格为 `YYYY-MM-DD` |
| end | 字符串 | **是** | 结束日，格式同上，**不能早于 start** |
| progress | 整数 | 否 | 0–100（画面上以 5 为单位调整），默认 0 |
| assignees | 字符串数组 | 否 | 担当，可多人；建议使用 `members` 里的名字 |
| level | 整数 | 否 | 层级：0 = 顶层，1–3 = 子任务，默认 0 |
| milestone | 布尔 | 否 | true = 以 ◆ 显示的里程碑任务（通常 start = end） |
| memo | 字符串 | 否 | 备注 |
| deps | 字符串数组 | 否 | 前工序任务的 id（任务关联） |
| color | 字符串 | 否 | 父任务的颜色，`#rrggbb` 格式；不写 = 按层级的默认色（第 1 层 `#6685ff`、第 2 层 `#20c997`、第 3 层 `#fab005`）。只对父任务有效，其他值会被忽略 |

### 项目里程碑

```json
{ "date": "2026-03-15", "title": "α版提出", "color": "red" }
```

| 字段 | 类型 | 必须 | 说明 |
|---|---|---|---|
| date | 字符串 | **是** | `YYYY-MM-DD` |
| title | 字符串 | 否 | 标题 |
| color | 字符串 | 否 | `blue` / `red` / `green` / `yellow` / `purple`，其他值会变成 blue |
| id | 字符串 | 否 | 省略时自动生成 |

### 公司休日

```json
{ "date": "2026-10-19", "color": "#e8590c" }
```

| 字段 | 类型 | 必须 | 说明 |
|---|---|---|---|
| date | 字符串 | **是** | `YYYY-MM-DD`，这一天不算工作日 |
| color | 字符串 | 否 | `#rrggbb` 格式的颜色，其他值会变成 `#e8590c`（橙） |

日本法定节假日已内置，不要写进这里。

## 13. 层级的表示方法（重要）

Tempo **不用「父任务 ID」字段**，而是用「顺序 + level」表示层级：

- 一个任务的子任务，是**紧接在它后面**、level 比它大 1 的任务
- 子任务结束于下一个 level ≤ 父任务 level 的任务之前

```
tasks 顺序         level   画面显示
设计               0       设计
  角色设计         1         ├ 角色设计
  场景设计         1         └ 场景设计
制作               0       制作
  建模             1         └ 建模
    粗模           2             └ 粗模
```

规则：

- level 每次最多比上一个任务**大 1**（不能从 0 直接跳到 2）
- 第一个任务的 level 必须是 0
- level 最大为 3
- **父任务的 start / end / progress / assignees 会被子任务的汇总值覆盖显示**，写了也不起作用；请把日期和进度写在最底层的任务上

## 14. 不需要写的值（程序自动计算）

以下内容**不存在数据里**，由程序计算，AI 不要尝试写入：

- 工作日数（「日数」列）
- 状态（完了 / 未着手 / 期限切れ / 進捗遅れ / 順調）
- 横条颜色、延迟等级
- 父任务的日期、进度、担当
- 全体進捗
- 关联导致的日期顺延（写入后程序会自动检查：前工序结束日 ≥ 后工序开始日时，后工序自动顺延）

## 15. 写入前自查清单（给 AI）

- [ ] JSON 语法正确（双引号、无尾随逗号、无注释）
- [ ] 包含项目的**全部**任务，而不仅是新增或修改的部分
- [ ] 每个任务都有非空的 `name`
- [ ] 所有日期都是 `YYYY-MM-DD`（如 `2026-02-02`，不是 `2026/2/2`）
- [ ] 每个任务 `end` ≥ `start`
- [ ] `progress` 是 0–100 的整数
- [ ] `id` 在项目内不重复；`deps` 里的 id 都真实存在，且不引用自己
- [ ] 第一个任务 level 为 0；level 每次最多 +1；最大为 3
- [ ] 日期和进度写在最底层任务上，而不是父任务上
- [ ] `assignees` 里的名字与 `members` 一致（写法、全角半角都要一致）
- [ ] 里程碑 `color` 只用 5 个允许值之一
- [ ] 结束日尽量不要落在周六、周日、节假日或公司休日（不会报错，但工作日数会与预期不同）
