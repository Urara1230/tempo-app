# Tempo 使い方マニュアル

[中文版](README.md)

Tempo はブラウザ上で動作するガントチャート（工程表）ツールです。タスクの日程計画、進捗確認、遅延の早期発見を目的としています。

- **開き方**：本フォルダ内の `Tempo.html` をダブルクリックします（Chrome または Edge 推奨）。インストール不要、オフラインでも利用可能です。
- **データの保存**：お使いのパソコンのブラウザ内に自動保存されます（画面右上に「このブラウザに保存」と表示）。
- **画面の言語**：日本語。本マニュアル内の「」で囲まれたテキストは、実際の画面上の表記に対応しています。

本マニュアルは以下の 2 部構成です：

- **第 1 部**：操作説明（ユーザー向け）
- **第 2 部**：データ形式仕様（AI、またはデータの一括登録を行う人向け）

---

# 第 1 部：操作説明

## 1. 画面構成

```
┌──────────────────────────────────────────────────────────────────┐
│ Tempo [プロジェクト▼] [＋プロジェクト] [設定] [保存] [担当者で絞り込み▼] [日|週|月] [今日] [＋タスク] │ ← 上部バー
│ 期間 … 次の節目 … 全体進捗 …%  [状態ラベル]                           │ ← 集計バー
│ [↶][↷] [コピー][貼り付け] [挿入][階層][移動] [リンク] [担当] [編集][＋][×] │ ← 編集ツールバー
├──────────────────────────┬───────────────────────────────────────┤
│ タスク表                    │ タイムライン（バー）                         │
│ タスク 担当 開始 終了 日数 進捗 │ ███████ 2/28 (土) 0% 18営業日 担当          │
└──────────────────────────┴───────────────────────────────────────┘
```

## 2. プロジェクト

- **新規作成**：「＋ プロジェクト」をクリック
- **切り替え**：上部左側のプルダウンメニューから選択
- **名前の変更 / 削除 / バックアップ**：「設定」をクリックして右側パネルを開く
- プロジェクトの削除は確認のためボタンを 2 回押す必要があります。**削除後は元に戻せません**

## 3. タスクの基本操作

| 操作内容 | 操作手順 |
|---|---|
| タスクの追加 | 「＋ タスク」をクリック、またはタスク表最下部の「＋ タスクを追加」をクリック |
| タスクの選択 | タスク行またはバーを**クリック**（Ctrl で複数選択、Shift で範囲選択） |
| 詳細編集を開く | タスク行またはバーを**ダブルクリック**、または選択中に Enter キー |
| 名前の変更 | タスク行を右クリック →「名前を変更」→ 入力後に Enter キー |
| 親タスクの色の変更 | 親タスクは階層ごとに自動で色が付きます（第 1 階層 青、第 2 階層 青緑、第 3 階層 黄）。色を変えたいときは親タスクの行を右クリック →「色」で色を選択（プレビュー）→「決定」で保存（「既定の色」= その階層の既定色に戻す） |
| 日付の変更 | バーの中央をドラッグ = 全体移動、バーの両端をドラッグ = 開始日 / 終了日の変更。**複数選択後にいずれかのバーの中央をドラッグすると、選択中のタスクがまとめて移動**（親タスクを選択した場合は、配下の子タスクも一緒に移動） |
| 進捗の変更 | バー右側の「N%」を**ダブルクリック** → スライダーで調整（「戻す」= 元の値に復元） |
| 担当者の指定 | タスク表の「担当」列の枠をクリック → メンバーを選択（複数選択可） |
| 順序の変更・子タスク化 | タスク行で**左クリックを約 0.35 秒長押し**し、目的の行へドラッグ：上部 = その上に配置、下部 = その下に配置、中央 = その子タスクにする。先に Ctrl / Shift で複数選択してから、そのうちの 1 行を長押しすると、選択したタスクをまとめて移動できます |
| 削除 | 選択後に Delete キーを 2 回押す、またはツールバーの × を 2 回クリック |
| 元に戻す / やり直す | Ctrl+Z / Ctrl+Y |

※ シングルクリックは選択のみで詳細編集画面は開かないため、ドラッグ操作時などに誤って編集画面が開く心配はありません。

## 4. 編集ツールバー

先にタスクを選択してから、ツールバーの各ボタンをクリックします。

| ボタン | 機能 | ショートカット |
|---|---|---|
| ↶ ↷ | 元に戻す / やり直す（Undo / Redo） | Ctrl+Z / Ctrl+Y |
| コピー / 貼り付け | 選択したタスク（子タスクを含む）をコピーし、選択行の下に貼り付け | Ctrl+C / Ctrl+V |
| 上にタスクを挿入 / 下にタスクを挿入 | 選択行の上、または下に新しいタスクを挿入 | |
| 子タスクにする / 階層を上げる | 直上のタスクの子タスクにする（インデント） / 1 階層上げる（アウトデント） | Tab / Shift+Tab |
| 上へ移動 / 下へ移動 | 同一階層内でタスクを上下に移動 | Alt+↑ / Alt+↓ |
| タスクをリンク / リンクを解除 | 選択した順序でタスクを前後工程として接続（矢印を表示）。親タスクは対象外 | |
| 担当者を追加 / 担当者を外す | 選択した複数のタスクの担当者を一括で追加 / 削除 | |
| 詳細を編集 | 詳細編集パネルを開く | Enter |
| ＋ / × | タスクの追加 / 削除（2 回クリック） | Delete 2 回 |

**リンクの効果**：前工程の終了日が延期された場合、後工程が自動的に後ろへ順延されます（営業日数は保持されます）。後方に順延されるのみで、自動で前倒しされることはありません。

## 5. 親タスクと子タスク

- 子タスクを持つタスクは「親タスク」となり、タイムライン上では細い集計バー（サマリーバー）として表示されます
- 親タスクの開始日・終了日・進捗・担当者は**配下の子タスクから自動計算**されるため、直接編集することはできません
- 最大 4 階層まで作成可能
- 親タスク左側の ▾ / ▸ をクリックすることで、子タスクを折りたたみ / 展開できます
- **親タスクの色**：タスクが親タスクになると、**自動で**階層ごとの既定色で表示されます：第 1 階層（最上位）青 `#6685ff`、第 2 階層 青緑 `#20c997`、第 3 階層 黄 `#fab005`。入れ子になった親タスクも区別できます。その行の左側に色の帯と薄い背景色が付き、集計バーも同じ色になるため、親タスクがひと目で分かります。色を変えたいときは親タスクの行を右クリック →「色」で色を選び →「決定」を押します。「既定の色」でその階層の既定色に戻せます。「色」は親タスクの右クリックメニューにのみ表示されます
  - 色を選んだ段階ではプレビューのみ（行とバーの色がすぐ変わります）で、「決定」を押すと保存されます。「決定」を押さずにメニューを閉じる（他の場所をクリック、または Esc）と元の色に戻ります

## 6. 色と状態の見方

### バーの色

| 表示色 | 意味 |
|---|---|
| 青 | 順調（予定どおり進捗している） |
| 青（右端が紫 → ピンクに変化） | 進捗遅れ。ピンクに近いほど遅れが大きい（4 段階でグラデーション表示） |
| 赤 → 黄 | 終了日を過ぎても未完了（期限切れ） |
| 灰色 | 完了済み |
| ◆ | マイルストーンタスク（1 日だけの節目タスク） |
| 細い青 / 青緑 / 黄のバー（行の左側にも同じ色の帯） | 親タスクの集計バー。階層ごとの既定色で、右クリックで色を変更可能（第 5 節参照） |

「遅れ」とは、経過日数から算出した「目標進捗（あるべき進捗）」を実際の進捗が下回っている状態を指します。たとえば 10 営業日のタスクで 5 営業日経過しているのに進捗が 0% であれば「遅れ」と判定されます。

### 状態（タスク名左側の丸印・上部の状態ラベル）

| 状態 | 判定条件 |
|---|---|
| 完了（灰） | 進捗率が 100% |
| 未着手（青） | 開始日がまだ到来していない |
| 期限切れ（赤） | 終了日（期日）を過ぎて未完了 |
| 進捗遅れ（橙） | 実際の進捗が目標進捗より 10 ポイント以上遅れている |
| 順調（緑） | 上記のいずれにも該当しない場合 |

上部の状態ラベルをクリックすると、その状態のタスクのみに絞り込み表示されます（もう一度クリックすると絞り込み解除）。

### その他

- **営業日**：土曜日・日曜日・日本の祝日（2028 年まで内蔵）および設定された会社の休日（第 7 節参照）を自動的に除外して計算します
- **全体進捗**：すべてのタスクの進捗率を営業日数で加重平均した数値です
- **タイムライン**：灰色背景 = 土日、ピンク背景 = 祝日、指定色 = 会社の休日、赤の縦線 = 今日。「今日」ボタンで今日の位置へスクロールします

## 7. プロジェクトのマイルストーン（大きな節目）

プロジェクト全体の重要な日程（納品日、中間チェックなど）を旗アイコンでマークします。

- **追加**：タイムライン上部の日付をクリック → 色を選択し、タイトルを入力 →「登録する」
- **変更 / 削除**：配置済みの旗アイコンをクリック
- 上部バーに直近の節目と残り日数が表示されます：「次の節目 3/15 α版提出（あと 12 日・8 営業日）」

### 会社の休日

会社独自の休日（創立記念日、年末年始、夏季休暇など）を**プロジェクトごとに個別設定**できます。日本の祝日は内蔵されているため、手動で追加する必要はありません。

- **休日に設定**：タイムライン上部の日付をクリック → ポップアップ内の「会社の休日」で色を選択 →「休日にする」
- **解除**：設定済みの日の日付を再度クリック →「休日を解除」
- **色の変更**：設定済みの日の日付をクリック → 色を変更すると即座に反映されます。次回新しく休日を設定する際も、最後に選択した色が初期値になります
- **効果**：その日は指定した色で表示され、営業日としてカウントされなくなります（営業日数計算、遅延判定、リンクによる自動順延にもすべて反映されます）
- **元に戻す**：Ctrl+Z で操作を取り消せます

## 8. メンバー名簿

事前にメンバーを登録しておくと、タスクの担当者を一覧からクリックで選択できるようになります。

1. 「設定」→「メンバー」欄に名前を入力 →「追加」（「、」で区切ると複数人を一度に追加可能）
2. タスク表の「担当」列の枠をクリックしてメンバーを選択

※ 名簿からメンバーを削除しても、すでにそのメンバーが割り当てられているタスクの担当設定には影響しません。

## 9. データの保存とバックアップ

- すべての変更は**自動で保存**されるため、手動保存の必要はありません
- データはお使いの**パソコンのブラウザ内（ローカルストレージ）**に保存されます。ブラウザの変更、パソコンの変更、閲覧データ（履歴・Cookie等）の消去を行うと表示されなくなります
- **フォルダへのバックアップ（推奨、Chrome / Edge）**：「設定」→「自動バックアップ」→「保存先フォルダを選ぶ」でフォルダを指定します。バックアップファイルはすべて指定したフォルダ内に保存され、いずれも**全プロジェクト**のデータを含みます：

  | ファイル名 | 保存タイミング | ファイル数 / 動作 |
  |---|---|---|
  | `auto.backup.json` | 変更を行うたびに自動保存（約 1 秒後） | 1 ファイルのみ（毎回上書きされ、常に最新状態） |
  | `2026-09-29_10-35-12.backup.json` | 上部バーの「保存」ボタンをクリックした時（ファイル名はクリック日時） | クリックごとに新規作成（上書きなし。特定バージョンを残したい時に使用） |
  | `before-restore.backup.json` | 「バックアップから復元」を実行する直前 | 1 ファイルのみ（復元直前の状態を毎回上書き保存） |

  - フォルダ未選択の状態で「保存」ボタンを押すと、最初にフォルダ選択ダイアログが表示されます
  - ブラウザ再起動後の初回変更時や保存時に、Chrome / Edge からフォルダへのアクセス許可を求められますので「許可」を選択してください
  - 「設定」パネル内に、保存先フォルダ名、自動バックアップの最新時刻、直近の手動保存ファイル名が表示されます
  - 保存先フォルダを Git リポジトリ内に配置しても問題ありません：`*.backup.json` はあらかじめ `.gitignore` に登録されているためコミット対象外となります
- **バックアップからの復元**：「設定」→「バックアップから復元」→ 復元したい `.backup.json` ファイルを選択します。ファイル内のプロジェクトデータは同一 ID のプロジェクトを上書きし、それ以外のプロジェクトはそのまま保持されます。復元後は `auto.backup.json` も復元内容で更新されるため、バックアップフォルダ設定済みの場合は、復元直前のデータが自動的に `before-restore.backup.json` へ退避保存されます。誤ったファイルを選んでしまった場合も、これを復元すれば元の状態に戻せます
- **プロジェクト単体のバックアップ**：「設定」→「JSONをコピー」で内容をコピーし、テキストファイルなどに貼り付けて保管します。復元時は「データ（JSON）」欄に貼り付けて「貼り付けたJSONで置き換え」を実行します
- `Tempo.html` のファイル移動やファイル名変更を行ってもデータは消えません（同一ブラウザ内であれば、ローカルファイル間で共通の保存領域が使われるため）

### Excel（.xlsx）の読み込みと書き出し

形式は Brabio（ブラビオ）の Excel 出力形式に準拠しています：1 行目がプロジェクト名、2 行目が期間、3 行目が見出しヘッダー（タイプ / アウトライン / ID / タイトル / 開始日 / 〆切日 …）、5 行目以降がデータ行（プロジェクト行 → マイルストーン → フォルダ / タスク）となります。

- **書き出し（エクスポート）**：「設定」→「Excel（.xlsx）」→「書き出す」。ファイル名は「プロジェクト名 (開始日～終了日).xlsx」となります
- **読み込み（インポート）**：「設定」→「読み込んで置き換え」→ .xlsx ファイルを選択。Brabio からエクスポートしたファイルもそのまま読み込めます
- 読み込みを実行すると**現在のプロジェクトの全タスクおよびマイルストーンが上書き置換**され、プロジェクト名やメンバー名簿もファイル内容に従って更新されます。誤って読み込んだ場合も Ctrl+Z で元に戻せます
- 読み込み完了後に「N 件のタスクを読み込みました」と表示されます。タイトルや日付が欠落している行は読み込まれずスキップされ、スキップされた件数がメッセージに表示されます
- 各列は見出し名（ヘッダー名）で認識されるため、Excel 側で列の並び順を変更していても問題ありません。日付表記は `2026/09/14` などの文字列、Excel の標準日付形式のどちらにも対応しています
- 項目の対応関係：アウトライン 1 = 最上位タスク、メンバーが複数名の場合は改行区切り、内容 = メモ（マイルストーン行の場合は色指定）、リンクID = リンク（依存関係）
- Brabio 形式の右側にある日別ガントチャート部分は書き出しません。末尾に Tempo 独自の「マイルストーン」列（◆ = マイルストーンタスク）と「色」列（親タスクの色。例：`#7048e8`）が追加されます（いずれも Brabio には存在しない項目です）
- ステータス、状況、進捗率などは Tempo 側で計算して書き出します。Brabio とは算出ロジックが異なるため、数値に多少の差異が生じる場合があります
- Brabio からエクスポートする際は期間を広めに設定してください（Brabio は設定期間外のタスクを出力しないため）
- 会社の休日は Excel に書き出されません（Brabio 形式に対応列がないため）。また、Excel を読み込んでも既存の会社の休日設定は保持されます

**Artifact（claude.ai）として公開した場合**：データはクラウドに保存され、画面上部に「クラウドに自動保存」と表示されます。リンクを開いた全員が同一のデータを参照でき、編集権限のないユーザーには「閲覧のみ」と表示されます。

## 10. よくある質問

| 困ったこと | 原因 / 対処法 |
|---|---|
| 親タスクの日付が変更できない | 親タスクの日付は配下の子タスクから自動計算されます。子タスク側の日付を変更してください |
| タスクをドラッグしようとするとテキスト選択になってしまう | タスク行を約 0.35 秒長押し（ホールド）してからドラッグしてください |
| 進捗「N%」をクリックしても反応しない | スライダーを開くには**ダブルクリック**が必要です |
| 担当者の候補に希望のメンバーが表示されない | 先に「設定」→「メンバー」で登録するか、詳細編集パネルで直接入力してください |
| データが見当たらない / 消えてしまった | 別のブラウザで開いているか、閲覧データ（履歴・Cookie等）を消去していませんか？「バックアップから復元」または保存済みの JSON から復元してください |
| バーが急にピンクや赤に変わった | 進捗の遅れ、または期限切れです。タスクの進捗率を更新してください |

# 第 2 部：データ形式（AI 向け）

本パートでは、Tempo のプロジェクトデータ構造と、AI が生成したデータを Tempo に書き込む手順について説明します。

## 11. 書き込み方法

### 方法 A：JSON の貼り付け（ローカル利用時・推奨）

1. Tempo で対象のプロジェクトを開く（新規作成の場合は先に「＋ プロジェクト」をクリック）
2. 「設定」→「JSONをコピー」をクリックし、**必ず事前に現在のデータをバックアップとして保存しておく**
3. AI は第 12 節の形式に従い、**完全な**プロジェクト JSON を生成する（差分や追加分のみではなく、現在のデータ全体をベースに編集する）
4. 生成した JSON を「データ（JSON）」欄に貼り付け →「貼り付けたJSONで置き換え」をクリック
5. 画面に「N 件のタスクを読み込みました」と表示されたら、件数が正しいか確認する。問題があれば Ctrl+Z で元に戻す

注意点：

- 「置き換え」を実行すると、**現在のプロジェクトの全タスクが上書き置換**されます。JSON に含まれていないタスクは削除されます
- `milestones`、`holidays`、`members`、`name` は、JSON 内にプロパティが存在する場合のみ置き換わります（記述しなかった場合は既存の値がそのまま維持されます）
- タスク配列 `[ {...}, {...} ]` のみを貼り付けることも可能です（その場合はタスクのみが置き換わります）
- **タスク名が空、または日付の形式が正しくないタスクは読み込まれません**。読み込み後にスキップされた件数が表示されますので、必ず件数を確認してください

### 方法 B：Artifact として公開後、クラウドデータベースへ直接書き込む

- コレクション（collection）名：`projects`
- ドキュメント ID = プロジェクト ID（1 プロジェクトにつき 1 ドキュメント）
- ドキュメントの内容 = 第 12 節のプロジェクトオブジェクト（`id` は含めない）＋ `updatedAt`（ミリ秒単位のタイムスタンプ）
- 書き込むと、ページを開いているユーザーの画面にリアルタイムで反映されます
- こちらも**完全上書き置換**となります。必ず既存のドキュメントを読み込み、それをベースに変更を加えた上で書き戻してください

## 12. データ構造

### プロジェクト

```json
{
  "name": "キャラクター制作",
  "members": ["山田", "佐藤", "鈴木"],
  "tasks": [ ...タスク、下記参照 ],
  "milestones": [ ...プロジェクトのマイルストーン、下記参照 ],
  "holidays": [ ...会社の休日、下記参照 ]
}
```

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| name | 文字列 | 任意 | プロジェクト名 |
| members | 文字列配列 | 任意 | メンバー名簿（担当者の候補一覧） |
| tasks | オブジェクト配列 | **必須** | タスク一覧（**配列の並び順 = 画面上の表示順**） |
| milestones | オブジェクト配列 | 任意 | プロジェクトのマイルストーン一覧 |
| holidays | オブジェクト配列 | 任意 | 会社の休日一覧（本プロジェクト専用） |

### タスク

```json
{
  "id": "t5",
  "name": "キャラ粗モデル制作",
  "start": "2026-02-02",
  "end": "2026-02-28",
  "progress": 0,
  "assignees": ["山田"],
  "level": 0,
  "milestone": false,
  "memo": "",
  "deps": ["t2"]
}
```

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| id | 文字列 | 推奨 | プロジェクト内で一意。省略時は自動採番されますが、その場合他タスクの `deps` から参照できなくなります |
| name | 文字列 | **必須** | タスク名（空文字不可） |
| start | 文字列 | **必須** | 開始日。形式は厳密に `YYYY-MM-DD` |
| end | 文字列 | **必須** | 終了日。形式は同上。**start より前の日付は指定不可** |
| progress | 整数 | 任意 | 0〜100（UI上は 5 刻みで調整）。デフォルトは 0 |
| assignees | 文字列配列 | 任意 | 担当者（複数指定可）。`members` に登録されている名前を推奨 |
| level | 整数 | 任意 | 階層レベル：0 = 最上位、1〜3 = 子タスク。デフォルトは 0 |
| milestone | 真偽値（boolean） | 任意 | true = ◆ マークで表示されるマイルストーンタスク（通常 start = end） |
| memo | 文字列 | 任意 | メモ |
| deps | 文字列配列 | 任意 | 先行タスク（前工程）の id 一覧（タスクのリンク依存関係） |
| color | 文字列 | 任意 | 親タスクの色。`#rrggbb` 形式。省略時は階層ごとの既定色（第 1 階層 `#6685ff`、第 2 階層 `#20c997`、第 3 階層 `#fab005`）。親タスクにのみ有効で、それ以外の値は無視されます |

### プロジェクトのマイルストーン

```json
{ "date": "2026-03-15", "title": "α版提出", "color": "red" }
```

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| date | 文字列 | **必須** | 日付（`YYYY-MM-DD` 形式） |
| title | 文字列 | 任意 | タイトル |
| color | 文字列 | 任意 | `blue` / `red` / `green` / `yellow` / `purple`（それ以外の値は `blue` にフォールバック） |
| id | 文字列 | 任意 | 一意のID（省略時は自動生成） |

### 会社の休日

```json
{ "date": "2026-10-19", "color": "#e8590c" }
```

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| date | 文字列 | **必須** | `YYYY-MM-DD`（この日付は営業日としてカウントされません） |
| color | 文字列 | 任意 | `#rrggbb` 形式のカラーコード（それ以外の値は `#e8590c`（オレンジ）にフォールバック） |

※ 日本の祝日は内蔵済みのため、ここには含めないでください。

## 13. 階層の表し方（重要）

Tempo は**「親タスク ID」フィールドを使用せず**、「配列の並び順 ＋ level（階層）」によって親子構造を表現します：

- あるタスクの子タスクは、**その直後に配置され**、かつ level が 1 つ大きいタスクとなります
- 子タスクの範囲は、次に親の level 以下のタスクが現れる直前までとなります

```
tasks の並び       level   画面上の表示
設計               0       設計
  キャラ設計       1         ├ キャラ設計
  背景設計         1         └ 背景設計
制作               0       制作
  モデリング       1         └ モデリング
    粗モデル       2             └ 粗モデル
```

ルール：

- level は直前のタスクより**最大で 1 だけ**大きくできます（0 からいきなり 2 にスキップすることは不可）
- 最初のタスクの level は必ず 0 にする必要があります
- level の最大値は 3 です（0〜3 の最大 4 階層）
- **親タスクの start / end / progress / assignees は子タスクの集計値によって自動上書き表示されます**（JSON に値を記述しても無視されます）。日付や進捗率は必ず最下層のタスク（葉ノード）に設定してください

## 14. 記述不要な項目（プログラムによる自動計算）

以下の項目は**データ内には保持されず**、プログラム側で都度自動計算されます。AI はこれらのプロパティを書き込まないでください：

- 営業日数（タスク表の「日数」列）
- 状態ステータス（完了 / 未着手 / 期限切れ / 進捗遅れ / 順調）
- バーの表示色、遅れ判定レベル
- 親タスクの日付、進捗率、担当者
- プロジェクト全体の進捗率
- リンクによる日付の自動順延（データ取り込み後、プログラムが自動判定します：前工程の終了日 ≥ 後工程の開始日となっている場合、後工程が自動的に順延されます）

## 15. 書き込み前のチェックリスト（AI 向け）

- [ ] JSON の構文（シンタックス）が正しい（ダブルクォーテーション使用、末尾カンマなし、コメントなし）
- [ ] 差分や追加分のみではなく、プロジェクトの**全タスク**を含んでいる
- [ ] すべてのタスクに空でない `name` が指定されている
- [ ] すべての日付が `YYYY-MM-DD` 形式になっている（例：`2026-02-02`。`2026/2/2` などの形式は不可）
- [ ] すべてのタスクで `end` ≥ `start` となっている（終了日が開始日より前になっていない）
- [ ] `progress` が 0〜100 の整数値である
- [ ] `id` がプロジェクト内で一意（重複なし）である。`deps` に指定した ID が実在し、循環参照や自己参照をしていない
- [ ] 最初のタスクの level が 0 である。level の増加幅は最大 +1 であり、最大値は 3 である
- [ ] 日付と進捗率は親タスクではなく、最下層のタスク（葉ノード）に設定している
- [ ] `assignees` に指定した名前が `members` の登録名と完全に一致している（表記揺れ、全角・半角スペース等も厳密に一致）
- [ ] マイルストーンの `color` は許可された 5 色（blue, red, green, yellow, purple）のいずれかである
- [ ] 終了日（期日）は極力、土日・祝日・会社の休日にしない（エラーにはなりませんが、営業日数計算が想定と異なる場合があります）

## 16. 完全な例

```json
{
  "name": "新キャラクター企画",
  "members": ["山田", "佐藤"],
  "tasks": [
    { "id": "a1", "name": "設計", "start": "2026-10-01", "end": "2026-10-01", "level": 0 },
    { "id": "a2", "name": "キャラ設計", "start": "2026-10-01", "end": "2026-10-09", "progress": 50, "assignees": ["山田"], "level": 1 },
    { "id": "a3", "name": "背景設計", "start": "2026-10-05", "end": "2026-10-16", "progress": 0, "assignees": ["佐藤"], "level": 1 },
    { "id": "a4", "name": "設計確認", "start": "2026-10-19", "end": "2026-10-19", "level": 0, "milestone": true, "deps": ["a2", "a3"] },
    { "id": "a5", "name": "モデリング", "start": "2026-10-20", "end": "2026-11-13", "assignees": ["山田", "佐藤"], "level": 0, "deps": ["a4"], "memo": "粗モデル → 仕上げ" }
  ],
  "milestones": [
    { "date": "2026-11-16", "title": "α版提出", "color": "red" }
  ]
}
```

説明：「設計」は親タスクであり、その日付は配下の子タスクの期間から自動的に 10/1〜10/16 と算出されるため、記述された日付は上書きされます。「設計確認」はマイルストーンタスクであり、2 つの設計タスクが両方完了してから行います。「モデリング」は「設計確認」の完了後に続きます。
